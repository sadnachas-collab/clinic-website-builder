## Что делаю

Добавляю в админ-панель новый раздел **«Уголок потребителя»** для управления документами и связываю его с одноимённым разделом сайта, чтобы загруженные документы реально отображались и скачивались посетителями.

## Что есть сейчас

На сайте (`public/clinic-site.html`) уже есть готовый блок `#view-consumer` с тремя категориями-аккордеонами:
1. Лицензии и реквизиты
2. Права и обязанности граждан
3. Контролирующие органы

Содержимое жёстко прописано в HTML — через админку сейчас никак не редактируется.

В админке (`public/clinic-admin.html`) есть отлаженный паттерн: сайдбар с `switchTab('xxx')`, секции `#section-xxx`, словарь `titles`, рендер-функции и сохранение в `localStorage` через `persistData()`.

## План

### 1. Новый пункт в левом меню админки
- Добавить в сайдбар кнопку «Уголок потребителя» (иконка `shield-check`) между «Подвал» и «Настройки».
- Добавить запись в словарь `titles`: `'consumer': 'Уголок потребителя'`.
- Добавить новую секцию `<div id="section-consumer" class="admin-section">` в основной контент.

### 2. Структура данных
Новое хранилище `dbConsumer` в `localStorage` — массив категорий:
```js
[
  {
    id, title: 'Лицензии и реквизиты', icon: 'file-badge-2',
    documents: [
      { id, name: 'Название документа', fileName: 'file.pdf',
        fileSize: '1.2 MB', dataUrl: 'data:application/pdf;base64,...' }
    ]
  },
  ...
]
```
По умолчанию заполнить тремя существующими категориями (без документов или с заглушками-ссылками), чтобы переход был бесшовным.

Также добавить блок «Контролирующие органы» — отдельный список объектов `{ name, address, phone }` (отдельно от документов, т.к. на сайте это карточки с телефонами, а не PDF).

### 3. UI раздела в админке
В `#section-consumer`:
- Список категорий-аккордеонов (в стиле остальных разделов).
- В каждой категории: редактируемое название + кнопка «Добавить документ».
- Карточка документа: название (input), кнопка загрузки файла, размер, кнопка «Удалить».
- Файлы храним как **data URL в base64 в localStorage**. Предупреждение: суммарный лимит localStorage — ~5 МБ; добавлю проверку размера файла (не больше 4 МБ на файл) с понятным сообщением. Для будущего масштабирования это можно вынести в облачное хранилище, но сейчас идём в том же стиле, что и весь сайт.
- Отдельный блок «Контролирующие органы» с CRUD карточек (название, адрес, телефон).

### 4. Логика (JS)
- `renderConsumer()` — отрисовка категорий и документов.
- `addConsumerDocument(catId)`, `updateConsumerDocument(...)`, `deleteConsumerDocument(...)`.
- `addConsumerCategory()`, `renameConsumerCategory(...)`, `deleteConsumerCategory(...)`.
- `addAuthority()`, `updateAuthority(...)`, `deleteAuthority(...)`.
- Сохранение через расширенный `persistData()` (добавить `localStorage.setItem('dbConsumer', ...)`).
- `initAllData()` — добавить `renderConsumer()`.
- Использовать существующие безопасные `readStoredData/readStoredArray`, чтобы битый кэш не валил админку.

### 5. Связка с фронтом
В `public/clinic-site.html`:
- Заменить хардкод трёх блоков в `#view-consumer` на динамический рендер из `localStorage.getItem('dbConsumer')`.
- Если в `localStorage` пусто — рисуем дефолтное содержимое (фолбэк), чтобы сайт продолжал работать у тех, кто ещё не открывал админку.
- Ссылки на документы: `<a href="${dataUrl}" download="${fileName}">…</a>` — клик скачивает реальный файл.

### 6. Проверка
- Открыть `/admin` → войти `admin/123456` → раздел «Уголок потребителя» виден и активируется.
- Загрузить тестовый PDF → сохранилось → на сайте в «Уголке потребителя» документ виден и скачивается.
- Перезагрузка страницы — данные на месте.
- Никаких `SyntaxError` в консоли, остальные разделы продолжают работать.
