## Причина «пустоты»

Раздел «Уголок потребителя» (`#section-consumer`) физически вложен внутрь `#section-footer` — у секции «Подвал» не хватает закрывающего `</div>`. Когда `switchTab('consumer')` снимает класс `.active` с подвала, тот становится `display:none`, и вместе с ним прячется весь HTML уголка потребителя. Поэтому экран пустой, ошибок в консоли нет.

## Что сделаю

### 1. Структурный фикс (главное)
- В `public/clinic-admin.html` перед строкой `<!-- ================== 6.5 СЕКЦИЯ УГОЛОК ПОТРЕБИТЕЛЯ ================== -->` добавлю недостающий `</div>`, закрывающий `#section-footer`. После этого блок уголка потребителя становится самостоятельной секцией на корневом уровне и корректно показывается по клику.
- Заодно проверю баланс тегов для остальных секций, чтобы не словить регресс.

### 2. Доработка раздела «Уголок потребителя» в админке
Сделаю раздел полноценным и логичным, в едином стиле с остальной админкой.

**Блок «Категории документов»:**
- Аккордеоны с явным разворачиванием/сворачиванием (как в других разделах), счётчик документов в заголовке.
- Выбор иконки категории из списка (lucide: `file-badge-2`, `scale`, `shield-check`, `book-open`, `landmark`, `folder`) — селектор вместо текстового поля.
- Поле «Описание категории» (опционально, выводится на сайте под заголовком).
- Кнопки: «Загрузить документ» (PDF/DOC/JPG до 4 МБ), «Переименовать», «Удалить категорию» с подтверждением.
- Карточка документа: название, имя файла + размер, дата загрузки, кнопки «Скачать» (проверка перед публикацией), «Заменить файл», «Удалить».
- Drag-and-drop порядок документов (стрелки ↑/↓) и категорий.
- Предзаполнение по умолчанию тремя реальными категориями: Лицензии, Права пациентов, Контролирующие органы (как было в исходном хардкоде сайта) с примерами-заглушками, чтобы раздел не выглядел пустым.

**Блок «Контролирующие органы»:**
- Сетка карточек: название, адрес, телефон, сайт (новое поле), email (новое поле).
- Кнопки: «Добавить», «Удалить» с подтверждением, стрелки порядка.
- Валидация телефона/email с подсветкой.

**Глобально:**
- Подсказка «Изменения сохраняются автоматически» + индикатор «Сохранено ✓» после `persistData()`.
- Toast-уведомления на все действия (добавил/удалил/загрузил/ошибка размера).
- Прогресс-бар занятого места в `localStorage` (предупреждение при >4 МБ суммарно).

### 3. Связка с сайтом
- В `public/clinic-site.html` функция `renderConsumerView()` уже читает `dbConsumer` — проверю, что:
  - корректно отображает иконку, описание категории, сайт/email органа;
  - сохраняет порядок категорий/документов из админки;
  - кнопка «Скачать» работает с `dataUrl` (base64), при пустом `dataUrl` показывает плейсхолдер «файл не загружен».

### 4. Проверка
- Открыть `/admin`, войти `admin/123456`, нажать «Уголок потребителя» — раздел отображается со всеми блоками и дефолтными данными.
- Загрузить PDF → видно в админке → видно на сайте → кнопка «Скачать» отдаёт файл.
- Добавить/удалить категорию и орган → сохранилось после перезагрузки.
- Никаких `SyntaxError` и пустых экранов; остальные разделы (Подвал, Настройки и т.д.) продолжают работать.
