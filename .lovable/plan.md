Понял по скринам: сейчас в разделе «Прайс-лист» сломаны две разные вещи — загрузка прайса упирается в права записи, а сохранение услуги пытается обновить строку с id `1`, хотя в базе id должен быть UUID.

План исправления:

1. Исправить права для текущего админа
- Проверить/обновить правила доступа так, чтобы админы с ролями `owner` и `editor` могли загружать документы и создавать/редактировать/удалять записи прайса и услуг.
- Отдельно учесть, что текущий пользователь уже есть в системе, но операции из браузера должны проходить через обычную админскую сессию.

2. Починить логику «Популярные услуги (витрина)»
- Убрать конфликт старой localStorage-строки с числовым id `1` и записей из базы с UUID.
- На старте раздела не показывать дефолтную услугу как будто она уже существует в базе; если база пустая — показывать пустой список или безопасно создать новую строку через кнопку «Добавить».
- Для новой услуги всегда использовать временный id вида `new_...`, а после успешного сохранения заменять его на UUID из базы.
- Для существующей услуги делать update только если id действительно UUID; иначе делать insert.
- После успешного сохранения перерисовывать строку в обычный режим, чтобы кнопки «Сохранить/Отмена» пропадали и возвращались «Редактировать/Удалить».

3. Починить загрузку и просмотр прайс-файла
- Исправить сохранение записи в `price_files`, чтобы ошибка `new row violates row-level security policy` больше не возникала.
- Не удалять старую запись до успешной загрузки и успешного создания новой записи, чтобы не терять текущий файл при ошибке.
- Добавить корректную обратную связь: «Загрузка…», «Файл загружен», понятная ошибка при проблеме прав/сети.
- «Просмотр» открывает публичный URL файла; если URL отсутствует — кнопка не активна.

4. Проверить в админке
- Загрузка прайса → запись появляется и просмотр открывает файл.
- Добавление услуги → строка появляется, сохраняется без ошибки UUID, возвращается view-mode.
- Редактирование цены существующей услуги → сохраняется и кнопки возвращаются в нормальный режим.
- Удаление услуги → запись пропадает без ошибок.
