# Сохранение не должно уводить с текущей вкладки

## Проблема

На `/admin → Главная → Базовые настройки и Контакты` после клика «Сохранить базу» открывается раздел **Обзор** (дашборд). Ожидается: остаёмся на «Главной».

## Что показал аудит кода

В `public/clinic-admin.html`:

- `saveBasicSettings()` (стр. 900) сама по себе вкладку не переключает — она читает поля `mp-*`, вызывает `persistData()` и `showToast(...)`.
- `persistData()` (стр. 757) пишет в `localStorage` и вызывает `updateDashboardStats()` — тоже без переключения.
- Единственное место, где меняется активная секция, — функция `switchTab(tabId)`.
- Класс `active` стоит **по умолчанию на `#section-dashboard`** (стр. 169) и на первой `.nav-btn` (стр. 89).

Значит «откат на дашборд» = что-то приводит к **повторной инициализации страницы или к сбросу активной секции к разметке по умолчанию**. Самые вероятные причины:

1. `mp-about-text` теперь обёрнут редактором Quill. При клике по кнопке внутри той же `<div class="bg-white ...">` фокус уходит из contenteditable Quill → срабатывают синтетические события (`input`/`change`), которые мы сами диспетчим в `attachRichEditor` (стр. 1372–1377). Если на каком-то предке висит делегированный обработчик (или Quill в режиме `theme: 'snow'` перехватывает submit/click) — это может вести к нежелательной перерисовке.
2. Кнопка `type="button"` стоит правильно, но **она находится внутри `.ql-toolbar`-«зоны» рядом с редактором, и при повторном `attachAllRichEditors(section-mainpage)` (запускается из обёртки `renderMainPageData`) состояние секции пересоздаётся**. Если где-то после сохранения вызывается `renderMainPageData()` (например через ререндер при `updateDashboardStats`), то могут сбрасываться display-стили.
3. Возможен скрытый submit формы/линка из-за HTML-разметки (нужно проверить вживую под девтулзами).

Без живого запуска точную причину не зафиксировать — статически в коде явного `switchTab('dashboard')` после сохранения **нет**.

## Что сделаем

### 1. Диагностика прямо в коде (одноразово, для подтверждения)

В `switchTab(tabId)` временно добавить `console.trace('switchTab →', tabId)`. Открыть `/admin`, перейти на «Главную», нажать «Сохранить базу» — увидим, кто и откуда вызвал переключение. После починки строку убрать.

### 2. Защита всех save-обработчиков

Сделать единый помощник `withStay(fn)`, который:

- принимает event, делает `e?.preventDefault()` и `e?.stopPropagation()`;
- запоминает `currentTab` (по `.nav-btn.active[data-target]`);
- вызывает `fn(...)`;
- после выполнения, если активная секция вдруг сменилась — возвращает её обратно через `switchTab(currentTab)` без анимации.

Применить ко всем кнопкам «Сохранить» в админке (актуальный список из аудита):

- `saveBasicSettings` — Главная, «Базовые настройки и Контакты» (та самая)
- `saveFooterData` — Подвал (2 кнопки: стр. 496 и 574)
- `saveProcEditorModal` — модалка процедуры
- `savePromo`, `saveReview`, `saveFaq` — карточки на Главной
- `saveRow` — услуги
- `saveCat` — категории каталога
- `saveSpecialist` — специалисты
- `saveAdmin` — настройки/доступы
- Сохранение в разделе «Уголок потребителя» (если кнопка использует свой обработчик — проверить и обернуть тем же `withStay`)

В разметке кнопки заменить `onclick="saveX()"` на `onclick="withStay(event, saveX)"` (или `onclick="saveX(event)"` с правкой сигнатуры — выберу единый стиль по месту, чтобы не плодить хаос).

### 3. Лечение корневой причины (после того, что покажет console.trace)

В зависимости от трассы:

- если триггер — синтетические `input/change`, которые мы сами диспетчим из Quill: убрать `change` (он лишний — сохранение в localStorage и так делается по кнопке) и оставить только `input`.
- если триггер — submit/клик по форме: добавить `e.preventDefault()` явно в `saveBasicSettings(e)` и поправить обработчик кнопки.
- если триггер — повторный `renderMainPageData` через цепочку обёрток: разорвать цикл (например, не вызывать `updateDashboardStats` через `persistData` после `saveBasicSettings`, а только обновить нужные счётчики).

## Что не трогаем

- Логику входа/выхода, structуру `localStorage`, рендеринг сайта `public/clinic-site.html`.
- Сам Quill и набор форматирования.
- Архитектуру разделов и `switchTab`.

## Проверка

1. `/admin`, логин `admin/123456`.
2. «Главная» → отредактировать телефон → «Сохранить базу». Ожидание: тост «Настройки сохранены», остаёмся на «Главной», скролл на месте.
3. То же для «Подвала» (обе кнопки), «Процедуры» (модалка), «Услуг», «Специалистов», «FAQ», «Отзывов», «Настроек» и «Уголка потребителя».
4. Перезагрузить `/admin` — данные подтянулись, активной осталась последняя выбранная вкладка не требуется (после reload по умолчанию дашборд — это ок).
