## Проблема

Учётка `admin` / `123456` в коде уже есть (массив `defaultAdmins` в `public/clinic-admin.html`) — отдельно «создавать администратора» не нужно. Войти не получается по другой причине:

В `public/clinic-admin.html` и `public/clinic-site.html` после конвертации из RTF в JS-блоках остались битые места — браузер ругается:

- `clinic-admin.html:631` — `SyntaxError: Unexpected token '<'`
- `clinic-site.html:217` — `SyntaxError: Unexpected end of input`
- `clinic-site.html:1132` — `SyntaxError: Unexpected token '<'`

Из-за этого весь `<script>` падает целиком, функция `handleLogin` не объявляется, и при сабмите формы вылетает `ReferenceError: handleLogin is not defined`. Браузер тут же делает дефолтный сабмит формы → iframe перезагружается → поля выглядят «очищенными». Это полностью объясняет ваш симптом.

## Что сделаю

1. Перечитаю оригинальные RTF-исходники из `docs/source/` (это эталон с Тильды) и сравню их JS со сконвертированными `public/clinic-admin.html` и `public/clinic-site.html`.
2. Найду в каждом из двух файлов конкретное место, где конвертер RTF→HTML сломал JS (типовые причины: HTML-сущности типа `&lt;` / `&amp;` внутри JS, оборванный шаблонный литерал, лишний `</script>`, неэкранированный `<` в строке).
3. Перепишу `rtf2html.py` так, чтобы он корректно обрабатывал содержимое `<script>` (не превращал `<`/`&` в сущности внутри скриптов, не резал по `</`), и перегенерирую оба HTML-файла из RTF. Это гарантирует, что мы остаёмся 1-в-1 с вашим оригиналом, без ручных «улучшений».
