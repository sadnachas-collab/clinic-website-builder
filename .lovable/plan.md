# Панель форматирования текста в админке

## Принцип

«Чем меньше свободы — тем меньше винегрета». Редактор подключаем **только к длинным описаниям**. Короткие поля (названия разделов, ФИО, телефоны, адреса, заголовки секций) остаются обычными `input` — заказчик физически не сможет сделать заголовок раздела курсивом 12px.

## Что будет уметь редактор

Строго фиксированный тулбар, одинаковый везде:

- **Ж** жирный, *К* курсив, <u>П</u> подчёркнутый, ~~З~~ зачёркнутый
- **Подзаголовок** (H3 в стиле сайта) и **Крупный текст** (lead-параграф) — два пресета, без свободного выбора px
- **Цвет**: только 2 акцента из дизайн-системы сайта — основной бренд-цвет и красный «важно». Никакого color-picker'а
- **Список** маркированный и нумерованный
- **Ссылка** (с авто-проверкой http/https)
- **Очистить форматирование** — на случай, если заказчик «перестарался»

Сознательно НЕ добавляем: выбор шрифта, размер в px, выравнивание, фон текста, таблицы, картинки внутри текста, цитаты — всё это источники разнобоя.

## Технически

- Подключаю **Quill 2** через CDN в `public/clinic-admin.html` (без сборки, проект статический).
- Создаю обёртку `initRichEditor(textareaEl)`:
  - прячет исходный `<textarea>`, рисует над ним div-редактор с урезанным тулбаром;
  - whitelist форматов: `bold, italic, underline, strike, header:[3], list, link, color:[brand,red]`;
  - на каждое изменение синхронизирует HTML обратно в `textarea.value` — чтобы вся текущая логика сохранения в localStorage продолжала работать без изменений;
  - вставка из Word/браузера прогоняется через `clipboard.matchVisual=false` — чужие стили срезаются.
- В `public/clinic-site.html` добавляю в `<style>` whitelist-классы Quill (`.ql-align`, `.ql-color-brand`, `.ql-color-red`, `h3` в content-блоках) — чтобы отформатированный HTML рендерился консистентно дизайну сайта.
- Места вывода на сайте (где сейчас `textContent = ...`) меняю на `innerHTML = ...` **только для тех полей, которые получили редактор** — остальные оставляем как есть, чтобы случайно не выполнить пользовательский HTML где не надо.

## Какие поля получают редактор

Прошёлся по `public/clinic-admin.html`, вот итоговый список длинных описаний:

**Главная страница**
- `mp-about-text` — описание клиники в блоке «О нас»

**Подвал и юр. документы**
- `ft-desc` — описание клиники в подвале
- `ft-policy` — политика конфиденциальности
- `ft-terms` — пользовательское соглашение
- `ft-consent` — согласие на обработку ПДн

**Услуги**
- `pe-desc` — описание услуги в редакторе

**Специалисты**
- `spec-edu-*` — образование врача
- `spec-bio-*` — биография врача

**FAQ / Процессы**
- `faq-a-*` — ответы в FAQ
- `tempEditProc.howItWorks[].a` — описание этапа «Как мы работаем»
- `tempEditProc.problems[].a` — решение в блоке «Проблемы»

**Отзывы**
- `rev-text-*` — текст отзыва

**Уголок потребителя** (раздел из прошлых итераций)
- описание категории документа
- любые длинные текстовые блоки внутри

Короткие поля (`mp-hero-title`, `mp-about-title`, названия услуг, ФИО, телефоны, e-mail, адрес, заголовки разделов и т.п.) **не трогаю** — там форматирование вредит.

## Проверка

1. Открыть `/admin`, войти `admin/123456`.
2. По очереди зайти в каждый раздел из списка выше, убедиться что над длинным полем появилась панель форматирования с нужным набором кнопок.
3. Сделать тестовое форматирование (жирный + подзаголовок + акцентный цвет + список), сохранить.
4. Открыть `/` — убедиться, что форматирование отображается, заголовки сайта не сломаны, мобильная вёрстка (974px и уже) в порядке.
5. Перезагрузить страницу админки — проверить, что форматирование подтянулось обратно в редактор из localStorage.

## Чего не трогаю

- Логику входа, структуру localStorage, архитектуру разделов.
- Короткие поля и системные заголовки.
- Раздел «Уголок потребителя» по структуре — только подключаю редактор к его длинным описаниям.
