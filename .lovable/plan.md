# Связать сайт с админкой через Lovable Cloud

## Подход

Сайт `public/clinic-site.html` сейчас содержит хардкод. Админка `public/clinic-admin.html` уже работает с Lovable Cloud через CDN-клиент Supabase. Идём тем же путём: добавляем в сайт инициализацию клиента и скрипты, которые при загрузке тянут данные из таблиц и подставляют в существующую разметку (там уже есть нужные `id` и контейнеры). Не переписываем сайт в React — это сохраняет единый стек с админкой и экономит недели работы.

## Шаг 1. Очистка тестовых данных

Удаляем всё, кроме `page_content` (тексты главной + подвал, которые вы уже редактировали в админке) и служебных таблиц (`admin_profiles`, `user_roles`).

Под удаление попадают:
- `services` (1), `specialists` (1), `procedures` (1), `procedure_categories` (4)
- `reviews` (1), `price_files` (1)
- `consumer_categories` (4), `consumer_documents` (3), `authorities` (2)
- `promos`, `faq`, `interior_photos`, `clinic_documents`, `requests` — уже пустые

Файлы из Storage (`photos`, `documents`), на которые ссылались тестовые записи, тоже удаляем, чтобы не висели.

## Шаг 2. Подключение сайта к Lovable Cloud

В `public/clinic-site.html` добавляется:

1. **CDN-подключение Supabase** (как в админке) — `@supabase/supabase-js` + инициализация публичным ключом.
2. **Модуль загрузки данных** — один файл `<script>` в конце страницы. Для каждой секции отдельная функция `loadX()`, все запускаются параллельно через `Promise.allSettled` после `DOMContentLoaded`.
3. **Безопасные плейсхолдеры** — пока данные не пришли, показываются скелетоны/скрытые секции (а не «битая вёрстка»). Если в таблице нет записей — секция целиком скрывается.

## Шаг 3. Маппинг таблиц → блоков сайта

| Таблица | Что заполняет на сайте |
|---|---|
| `page_content` (`main_texts`) | Заголовок hero, подзаголовок, бегущая строка преимуществ |
| `page_content` (`footer`) | Адрес, телефоны, режим работы, соцссылки в подвале |
| `interior_photos` | Карусель интерьера на главной (`#hero-interior-slides`) |
| `promos` | Блок акций на главной |
| `procedure_categories` + `procedures` | Раздел «Услуги/Процедуры» — категории и карточки |
| `specialists` | Раздел «Наши врачи» + модалка врача (`#doctor-modal`) |
| `reviews` | Блок отзывов |
| `faq` | Аккордеон вопросов |
| `price_files` | Кнопки скачивания прайсов |
| `consumer_categories` + `consumer_documents` | Раздел «Уголок потребителя» |
| `authorities` | Контролирующие органы |
| `clinic_documents` | Документы клиники (лицензии и т.п.) |

Записи фильтруются по `published = true` (где есть поле) и сортируются по `sort_order`.

## Шаг 4. Проверка

1. После очистки открыть превью — сайт должен показать пустые состояния (без скелетонов навсегда и без ошибок в консоли).
2. Через админку добавить по одной записи в `services`, `specialists`, `promos`, `reviews`, `faq` → обновить главную страницу → убедиться, что данные появились.
3. Загрузить фото врача и интерьера → проверить, что картинки из Storage отображаются.
4. Загрузить PDF в `price_files` → кнопка скачивания работает.
5. Проверить «Уголок потребителя» и модалку врача.
6. Проверить консоль: нет 401/403 (значит RLS-политики на чтение публичные — они уже такие).

## Технические детали

- Никаких изменений в БД (схема, RLS, триггеры) не требуется — все нужные таблицы уже доступны на чтение для `anon`.
- React/TanStack-роуты не трогаем: сайт остаётся статическим HTML в `/public/`, как и сейчас.
- Сторонние библиотеки не добавляются — только Supabase CDN, который уже используется в админке.
- Удаление данных делается через прямые SQL-операции (insert/update/delete-tool), не миграцией.
- Один большой `<script type="module">` в конце `clinic-site.html` — без сборки и бандлера.

## Что НЕ делаем в этом этапе

- Не трогаем форму записи (она ушла в DIKIDI).
- Не трогаем админку — она уже работает.
- Не настраиваем SEO/домен/публикацию — это следующий этап.
